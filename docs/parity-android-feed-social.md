## Highest-priority safe change made

React Native loads a user’s followed topics and passes a selected topic into For You feed requests. Android previously omitted the topic list and filter. This pass adds the authenticated topic-list request, parsing, selectable chips, topic-aware initial and paginated feed requests, and clearing the filter on feed-mode changes. Following requests deliberately ignore a topic ID. The API base remains build-configured, and request construction stays in `FeedRepository`.

## Android design guidance applied

Use Material controls and Compose semantics for the newly actionable item; preserve a distinct touch target and spoken action label. Broader implementation should continue adapting to window size/form factor rather than assuming phone-only layouts. This is consistent with Android’s [app quality and multi-form-factor guidance](https://developer.android.com/get-started/overview) and [Android UI design guidance](https://developer.android.com/design/ui).

### Clips watch-event parity checkpoint — 2026-11-06

- Android now tracks the active accessible clip's visible duration and playback progression, ignores seek discontinuities, counts natural loops, and submits one view per clip/account plus dwell and watch summaries through the existing authenticated `POST /api/v1/feeds/interactions/batch` contract. It skips clips authored by the viewer or their active acting profile and records only after the same 2-second visibility threshold used by RN. Events are sanitized, account-scoped and durably queued (hashed account key, no credentials) with RN's 500-event cap and batch size 50; failed sends remain for the next flush.
- Responsibility wiring for the tracker and Clips data repository moved into `SignedInRepositories`; `SignedInApp.kt` is now 499 lines. A fresh Kotlin source scan found no `.kt` file above 500 lines; largest files are `SignedInApp.kt` (499), `MessagesScreen.kt` and `MessagesRepository.kt` (495 each), and `SpacesScreen.kt` (482).
- Verification: focused watch-session/repository suite passed (**11 tests**), and production Kotlin plus `:app:compileDebugAndroidTestKotlin` passed. No emulator/device is attached; runtime video playback remains unverified. The full Android suite was previously green on this worktree (**525 tests**), but was not rerun after this Clips addition. `git diff --check` passed.

### Home wallet preview follow-up — 2026-11-04

Android now displays a signed-in-only, read-only Wallet summary in Home, including when feed results are loading, empty, or unavailable, and provides a direct Wallet action. It uses the existing authenticated wallet repository and keys state by account identity so changing accounts reloads and clears prior summary state. Metric layout switches to a vertical arrangement at narrower card widths and allows values to wrap. Compose test source covers guest suppression, loading/data/error-retry, navigation callback, and account switching. The serialized Kotlin build and 207 JVM tests passed; instrumentation sources compiled, but no device was available to run UI tests. This closes the Home wallet-preview gap only; RN's curated modules and media creation/playback remain incomplete in Kotlin.
