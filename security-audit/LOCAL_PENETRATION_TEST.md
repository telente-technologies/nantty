## Ads withdrawal idempotency race — 2026-10-29

- Added a bounded test with 16 simultaneous identical withdrawal requests, one synthetic settled balance, unique valid step-up tokens and a fake in-memory wallet adapter. The first reproduction returned 422 `WITHDRAWAL_ABOVE_AVAILABLE` to some requests after the first transaction reserved funds, even though every request used the same idempotency key. Database and fake-wallet state did not show duplicate payout, but the retry response violated the idempotency contract.
- Fixed `WithdrawAdBalance` reservation handling to re-check the user/key inside the transaction after locking the account row. `ADS_TEST_DATABASE_URL=... go test ./modules/ads -run '^TestConcurrentWithdrawalReplayCreatesOnePayoutAndLedgerDebit$' -count=1` passed; the same test under `go test -race` passed. Assertions verified 16 successful responses with one withdrawal ID, one withdrawal row, one ledger debit, one downstream payout and exactly 150000 NGN minor units remaining from 400000 after a 250000 withdrawal.
- The full `ADS_TEST_DATABASE_URL=... go test ./modules/ads -count=1` passed after the fix. This is a local single-process test with a fake adapter; different-key simultaneous withdrawals, multi-instance contention and real wallet/provider idempotency remain unverified.
