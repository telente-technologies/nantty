# Remaining security risks and verification gaps

Updated 2026-10-29. This list is evidence-scoped; absence of reproduction is not a pass.

## Launch blockers / high-priority unresolved

- **AUD-DB-001:** all six money schemas now use separate `svc_migrator` ownership and a pre-rollout one-shot migration; startup migration is disabled. Disposable PostGIS verified repeat migrations, runtime DDL/role-escalation denial and ledger posting/rollback. **Still a deployment gate:** AWS role provisioning, schema/table grants, ECS task definition, secret/IAM/KMS/network access and workflow execution were not inspected or tested. The local bootstrap's broad DML default grants across money schemas also need a table-by-table operation/privilege review before claiming strict minimum-DML privilege. Do not claim production readiness until these are reviewed and an isolated staging smoke test passes.
- **AWS migration setup:** actual staging/prod database roles, grants, task-definition family, secret reference, KMS/task execution permissions, network access and rollback are external/manual and unverified. Mock AWS task tests do not verify those resources.
- **Provider egress:** Terraform defaults runtime and payment HTTPS CIDR lists to empty (deny direct internet) and rejects `0.0.0.0/0`. Source uses Flutterwave, Smile Identity, Apple/Google billing/auth, Cloudflare challenge, Expo push and AWS endpoints. No DNS/IP resolution or provider request was performed. CIDR allowlists may not safely express changing provider hostnames; implement a reviewed domain-aware egress proxy/private endpoints before claiming working provider connectivity.
- **Production admin gate:** staging/prod require owner-selected trusted staff CIDRs and correct forwarded-source semantics. Values are commented/unset in checked-in prod/staging examples; no plan/apply was run.
- **Space route:** unit/static routing is verified; no live gateway→Go endpoint, authenticated caller, or service failure propagation was tested.

## Not dynamically assessed

Auth/signup/OTP/session/recovery handlers were exercised through the real Go auth module HTTP test server against disposable Postgres and Valkey, but not through the deployed-style Go API/gateway. Most horizontal/vertical authorization and tenant isolation remain unverified. Payment fake-provider and selected webhook/refund race scenarios passed; live provider signatures/ingress, payouts, wallet/escrow HTTP workflows and other money races remain unverified. Media upload HTTP was tested with fake in-memory storage, but deployed S3/private-media permissions and malware scanning remain unverified. Browser XSS/CSRF/storage, live WebSocket room isolation, Redis/queue ACLs and duplicate jobs, service-level load/recovery, cloud WAF/IAM/security-group state, Git history and complete dependency/image scans remain unverified. The users privacy integration passed with synthetic identities, verifying address ownership isolation plus consent and deletion/retention behaviors; it does not cover other resources. Gateway tests exercise signed-token enforcement and synthetic rate limiting against fake upstreams, not ownership inside those upstreams. A 20-request gateway burst only verifies the configured rate-limit boundary and is not a capacity benchmark. The broad payment test command still fails five Apple/Google fixture cases (missing Apple marker OIDs and invalid fixture signature/claims); these are test-fixture failures, not evidence of an exploit. See `TEST_COVERAGE.md` for exact commands and results.

Payment package unit/integration tests were run against a disposable database and fake provider. A verified underpaid-intent state bug was fixed and targeted regressions passed. The whole `./modules/payments/...` tree is still not clean because Apple/Google signature fixtures fail. This does not verify the running gateway-to-payment service, actual webhook ingress/replay, settlement operations across production-shaped role grants, or wallet/escrow/payout paths. A refund reference race passed after correcting its test fixture; the test was not run against a deployed multi-instance service.

## Safety / release status

No production/cloud resources, real provider endpoints, personal data, real transfers, commits, pushes or deployments were accessed. Current overall security readiness is **not production-ready** on the evidence in this report: AWS migration-task provisioning and minimum table-level DML grants remain unverified, and multiple high-impact surfaces remain untested. Complete the database staging gates, then run the full isolated service security matrix and a controlled staging review.

Wallet and escrow module suites now pass against a disposable local PostGIS DB, and both package suites pass under `go test -race`. This is bounded module/harness evidence only; the full-stack HTTP/auth path and production-shaped multi-instance/provider/queue operations remain unverified. The wallet integration harness was corrected to apply its embedded migration bundle in the isolated test schema; runtime source was not changed.

Inventory and orders also pass their full Go package tests against disposable PostGIS; selected stock-reservation, coupon-limit and invoice-number concurrency cases pass under `-race`. The order suite includes one buyer ownership regression. These results narrow the gap but do not verify the complete storefront-to-payment-to-escrow path, all object authorization boundaries, distributed concurrency or real queue replay.

Ads: full package integration tests and a 16-request same-idempotency-key withdrawal race pass on isolated synthetic Postgres after fixing the local retry-response race. This found no duplicate payout/double debit. Concurrent different-key withdrawals, multi-instance replay, real wallet settlement and provider ingress remain unverified.

The payment intent fails, finance review is recorded, and no escrow is created in the synthetic case. Real provider behavior and deployed service integration remain unverified.

The dedicated runtime-role privilege test was not enabled because the expected exact role/schema fixture was not provisioned.
