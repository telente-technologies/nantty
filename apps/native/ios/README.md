# Nantty native iOS foundation

This is a native SwiftUI app and WidgetKit extension, defined with XcodeGen in `project.yml`. Generate the Xcode project with `xcodegen generate`, then open `Nantty.xcodeproj` in Xcode. The app and widget use bundle identifiers `com.nantty.app` and `com.nantty.app.widget` and share the `group.com.nantty.app` app group.

The app includes a public For You feed backed by `GET /api/v1/feeds/for-you` and a Following feed backed by authenticated `GET /api/v1/feeds/following`. The adaptive system segmented picker switches between them. Following is gated in both the SwiftUI view and `SessionModel`: the request is never sent while signed out, its bearer token is read from the device Keychain through `SessionModel`, and the feed service also refuses a missing/blank token. A rejected authenticated request clears the local session and returns to a sign-in gate rather than falling back to public feed data. Feed state and cursor are cleared when changing feed or session; responses completing after the selected feed/account changes are discarded. Both feeds use server cursor continuation, duplicate removal, and accessible loading, retry, empty, and end states. Signed-in viewers receive their own Like/Repost state in each feed and can Like/Unlike or Repost/Undo from a feed row; failed requests do not change the displayed counts, and signed-out viewers are sent to Account without a write request. Selecting a post opens an API-backed thread with nested replies and media/video-reply previews; signed-in users can reply, like/unlike, and repost/undo from the detail screen. Signed-in users can also create a plain text post from the feed toolbar or split-view navigation. The composer requires non-whitespace text, enforces the backend's 2,200-character limit, sends only `text` and `kind: "post"` to authenticated `POST /api/v1/posts`, and sends an `Idempotency-Key` for retry safety. It provides progress, recoverable error, and success states; returning to the feed recreates and reloads the feed view. No media upload, scheduling, or unauthenticated publishing is included. These actions use the existing bearer-authenticated API routes and Keychain-backed session boundary. Sign-in calls `POST /api/v1/auth/login`; session restoration rotates credentials through `POST /api/v1/auth/refresh` and loads the current user from `GET /api/v1/users/me`; sign-out calls bearer-authenticated `POST /api/v1/auth/logout`. API origin is build-configured: Debug defaults to `http://localhost:8080` and allows loopback HTTP or HTTPS development origins; Release is pinned to the compiled `https://api.nantty.com` origin. Release rejects arbitrary host/port overrides before requests are made. The account UI has validation, progress, recoverable restoration, and server-error states.

The Notifications destination provides the native Activity inbox using authenticated `GET /api/v1/notifications?filter=all|mentions&cursor=...`, `POST /api/v1/notifications/{id}/read`, and `POST /api/v1/notifications/read-all`. It uses server cursors, removes duplicate rows across pages, and supports pull-to-refresh, loading, retry, empty, and pagination states. Read actions update local rows only after the server confirms them. Requests are gated through `SessionModel` and the Keychain credential store; expired credentials are cleared, and responses completing after an account or filter change are discarded. Notification taps route validated post IDs to post threads and accepted follow-request notifications to the actor profile; other notification kinds remain non-navigable unless a supported, validated destination is added.

Access and refresh tokens are stored together in the device Keychain with `WhenUnlockedThisDeviceOnly` accessibility. Passwords are never persisted. Account state and tokens are not written to UserDefaults or the widget app group. The Orders widget receives only a bounded snapshot of active order status, reference, item/store labels, and optional ETA; image URLs, server-supplied links, balances, and credentials are excluded. The snapshot is account-fingerprinted to prevent one signed-in account from displaying another account's cached orders, marked stale after 30 minutes or a failed refresh, cleared on sign-out, and redacted by WidgetKit privacy-sensitive rendering.

The API URL stays in the app's private preferences. The host app fetches `GET /api/v1/widgets/orders` through the Keychain-backed session boundary when a session is restored, signed in, or the app becomes active, then asks WidgetKit to reload the Orders timeline. The widget extension reads only the sanitized order snapshot from app-group `UserDefaults`; it never makes network requests or reads Keychain credentials. A `nantty://orders/{id}` tap is registered in the app plist and routes into the authenticated native Orders view. Keep app-group data minimal and never put credentials, wallet/balance data, or raw API responses there.

The Quick Actions widget uses only existing app destinations and app-owned `nantty://` links: `feed`, `create`, `wallet`, and `messages` (plus the existing `orders` route). Its small and medium layouts use system widget surfaces and accessible `Link` controls. It contains no account-specific data, wallet balance, messages, or credentials; the app applies its normal sign-in gates after opening a destination.

## Apple design guidance used

- [Technology Overviews: Interface fundamentals](https://developer.apple.com/documentation/technologyoverviews/interface-fundamentals)
- [UI Design Dos and Don'ts](https://developer.apple.com/design/tips/)
- [Human Interface Guidelines: Layout](https://developer.apple.com/design/human-interface-guidelines/layout)
- [SwiftUI](https://developer.apple.com/swiftui/)
- [Prepare your app for iPhone Duo](https://developer.apple.com/videos/play/tech-talks/111461/)
- [Technology Overviews: Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/liquid-glass)
- [Human Interface Guidelines: Materials](https://developer.apple.com/design/human-interface-guidelines/materials)

The shell uses system navigation and form controls, size-class-aware split navigation, Dynamic Type-compatible text, semantic colors, and safe-area-respecting layouts. Standard navigation, list, and form containers keep content within system-reserved regions. Standard system chrome receives the platform's Liquid Glass treatment where supported; no custom decorative glass surfaces are added. Layout decisions do not depend on a specific device model, orientation, hinge, or reserved region. SwiftUI scene state owns one shared account session while selection and form state remain local to each window.

The unit-test target covers login/refresh JSON decoding, validation, transport URL policy, For You/Following route and cursor construction, Following bearer-token enforcement and signed-out gating, notification route/filter/cursor construction and authenticated session gating, session expiry, cursor deduplication, text-post constraints, Keychain-session enforcement, and the authenticated idempotent post request contract. Full simulator execution still requires Xcode and XcodeGen.

## Build availability

XcodeGen and Xcode are required to generate and build the project. The checked-in XcodeGen definition is the source of truth; the generated `.xcodeproj` is not committed.

## App icon

The iOS app uses the approved artwork from `docs/design/assets/nanttyAppIcon.png`, mechanically center-cropped and resized to an opaque 1024×1024 PNG at `Nantty/Assets.xcassets/AppIcon.appiconset/AppIcon.png`. The source artwork is left unchanged. `project.yml` selects the `AppIcon` asset catalog for the app target.

To regenerate the project and build locally, install XcodeGen and Xcode, then run `xcodegen generate` and build the `Nantty` scheme for an iOS destination in Xcode. The asset catalog JSON and PNG dimensions/opacity can be validated on other systems, but Xcode asset compilation has not been verified in environments without Xcode.
