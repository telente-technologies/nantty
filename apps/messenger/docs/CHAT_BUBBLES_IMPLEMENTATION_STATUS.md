# Chat Bubbles implementation status

Status reflects source inspection and commands run in this workspace, not a production release.

| Requirement | Status | Evidence / gap |
| --- | --- | --- |
| In-app floating conversations | Implemented, partially verified | Existing draggable multi-conversation UI is wired to the encrypted conversation screen. The app-shell host remains available across Chats and Stories, and stays hidden in Settings or over a full conversation. Its master preference and active conversation IDs are local and independent of Android system-bubble selection. Drafts are isolated by account and conversation in the existing AEAD-sealed SQLite record store and are cleared with Messenger crypto/session cleanup; adapter tests verify persistence, deletion, isolation and write ordering, while real Expo SQLite process-recreation/account-switch behavior remains unverified on device. An accessibility action can dismiss a collapsed bubble without dragging. |
| Android data-only delivery for bubble-eligible chat | Implemented, unit verified | Notifications FCM sender omits the `notification` object only when `bubbleAllowed=true`; regression tests verify high priority, generic content, stable message ID, and bubble preference fields admitted by the event schema. |
| Android bubble shortcut and metadata | Implemented, unverified | Expo presentation delegate adds `MessagingStyle`, stable long-lived shortcut, conversation-associated notification channel and `BubbleMetadata`, with ordinary-notification fallback if the OS/channel refuses bubbles; a non-exported `NanttyBubbleActivity` hosts the compact route. Android Gradle compilation and device behavior remain unverified. |
| Compact Android bubble route | Implemented, unverified | Shortcut includes `surface=bubble`; RN opens only the authorized compact conversation route through the dedicated bubble Activity. |
| Android capability/status and local test action | Implemented, unverified | App-scoped native module checks API support, runtime permission and Android bubble allowance, opens system bubble settings and per-conversation channel settings, posts a local MessagingStyle bubble notification, and clears shortcuts/notifications on logout. It cannot reliably report whether the OS actually displayed the bubble. |
| Guided Android setup wizard | Implemented, unverified | First enable explains the feature, checks Android support before requesting anything, requests notification permission once before directing repeat declines to settings, registers this Messenger installation's FCM token, checks bubble capability, directs users to system settings when required, and reports unsupported Android versions without claiming setup succeeded. Runtime and OEM-specific paths still require device testing. |
| Conversation bubble preferences | Implemented, partially verified | Settings supports None, All, and a searchable list of authorized conversations from the existing inbox API. Inbox/header actions are explicitly labeled as in-app bubbles. Android conversation headers can open per-conversation channel settings after Android has created that channel. |
| Android notification quick reply | Implemented, unverified | Expo text-input action foregrounds Messenger; the response handler uses existing authorization, encrypted send and a deterministic digest-based idempotency key. Failed replies open the conversation and show a retry prompt. Native/runtime and cold-process tests are not available. |
| iOS interactive notification reply | Implemented, unverified | Registered Expo notification category has text input and mark-read actions; reply foregrounds Messenger for secure processing. No iOS build/device available. |
| Interactive notification preference enforcement | Implemented, unit verified | Action categories are registered only for a signed-in session; reply and mark-read responses re-read the saved preference and fail closed to opening the conversation if disabled or unreadable. Pure decision tests cover enabled/disabled and unrelated action identifiers; Expo OS callback behavior remains unverified. |
| Local notification test | Implemented, unverified | Settings can post a generic local test alert on supported platforms; copy explicitly distinguishes this from remote delivery or reply verification. |
| Per-conversation Android notification channel | Implemented, unverified | Bubble-eligible delivery creates a stable conversation channel associated with the published shortcut, carries parent channel sound/vibration/lock-screen visibility at creation, and does not rewrite an existing channel. Runtime system behavior remains unverified. |
| iOS system bubbles | Correctly unsupported | No overlay, PiP or private API workaround is used. |
| Push-token routing | Implemented per explicit policy; backend/provider tests passed, device unverified | User chose to keep notifications in both apps. Messenger Android registers FCM and uses the custom data-only bubble pipeline; the main Nantty app registers Expo and keeps its normal alert. The dispatcher sends to both provider groups. Messenger iOS remains Expo. Same-provider duplicate installations/stale tokens are not independently correlated, and end-to-end delivery was not device-tested. |
| Encryption, membership and offline send | Existing infrastructure reused; bubble path unverified | Existing E2EE service, authorized conversation fetch, encrypted SQLite outbox and retry path are reused. No native-surface security acceptance tests were run. |
| Expanded Android activity architecture | Partially implemented, unverified | Android opens the compact route in a `NanttyBubbleActivity` derived from the existing React Native `MainActivity`. This avoids a second messaging implementation and retains the existing authorization/E2EE path, but starts a React Native activity surface per bubble; memory/startup impact and concurrent surface behavior are unmeasured and need device testing/architecture work. |
| Account/revocation cleanup | Implemented in source, unverified | Sign-out immediately hides the signed-in UI and removes local refresh/trusted-device credentials before best-effort network/native cleanup. Terminal refresh/retry authorization failures (401/403) use the same path. Cleanup clears encrypted chat state, decrypted media, realtime, bubble preferences, push registration, the last notification response, native notifications and `nantty-chat-*` shortcuts. On API 30+, long-lived shortcuts are removed; API 25–29 pinned shortcuts are disabled and dynamic ones removed. Native cleanup behavior and remote device revocation still need device/API integration tests. |
